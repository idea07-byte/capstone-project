1. Objective

The objective of this practical work is to design and test the relational database for a Multi-Vendor E-Commerce Platform (BuyIt). The work covers table creation, primary and foreign keys, sample data insertion, JOIN operations, composite keys and intentional SQL error testing for debugging practice.

2. Database Structure

The database contains 17 tables: users, vendors, categories, brands, products, product_images, addresses, coupons, orders, order_items, payments, cart, cart_items, wishlist, wishlist_items, reviews, and notifications.

The relationships are implemented using primary keys and foreign keys. Examples include users -> vendors, vendors -> products, orders -> order_items, and so on.

3. Table Creation & Key Constraints

The schema was created using BIGINT primary keys with AUTO_INCREMENT where appropriate. Foreign keys were added to maintain referential integrity between related tables. UNIQUE constraints were used for fields like email.

The final schema contains 17 tables and the foreign key relationships were verified in MySQL 8.4 Command Line Client.

5. JOIN OPERATIONS

Join operations were used to retrieve related information from multiple tables. The queries below use the actual table names instead of short aliases, making the relationship between tables easier to understand during the practical.

5.1 INNER JOIN

Returns only records that have matching values in both tables.

MySQL 8.4 Command Line Client ×
− □ ×

5.2 LEFT JOIN

Returns all rows from the left table, plus matched rows from the right table. Unmatched right-side columns come back as NULL.

− □ ×

All rows from the right table, matched rows from the left, NULL where there is no match.

5.4 FULL JOIN

All rows from both right and left tables, with NULL on whichever side lacks a match.

5.5 NATURAL JOIN

Automatically joins two tables on all columns that share the same name—you don’t specify the ON condition yourself. MySQL compares every identically named column and matches rows where all of them are equal.
